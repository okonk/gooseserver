# Pet Death and Recall Cooldown Implementation Plan

**Goal:** Prevent an individual pet from spawning for 120 seconds after death or manual recall while leaving automatic cleanup cooldown-free.

**Architecture:** Keep `Pet.Destroy` as the no-penalty teardown path and add a dedicated `Pet.DestroyWithCooldown` path for death and owner recall. Represent `NextRespawnTime` as a persisted UTC Unix timestamp in seconds, using the existing database column, and enforce it in `/petspawn`.

**Tech Stack:** C# 13, .NET 10, SQLite/System.Data.SQLite, xUnit

---

## APIs Verified

- `Pet.NextRespawnTime` is the in-memory cooldown field, while `RespawnTime` is the existing per-pet duration copied from the source NPC: `Goose/Pet.cs:62-70`, `Goose/Pet.cs:172`.
- Pet loading already reads `next_respawn_time`: `Goose/Pet.cs:201-290`, specifically `Goose/Pet.cs:277`.
- The existing pet insert and update builders omit `next_respawn_time`: `Goose/Pet.cs:299-454`.
- The existing schema already defines `next_respawn_time BIGINT DEFAULT 0 NOT NULL`: `Goose/sql/pets.sql:2-10`. No schema migration is required.
- `Pet.Destroy` removes a live pet from map, aggro, and login-ID registries and returns without mutation when the pet is already absent: `Goose/Pet.cs:508-544`.
- Pet death currently routes through `Pet.Attacked` and calls ordinary `Destroy`: `Goose/Pet.cs:748-806`.
- Manual recall is `SpellEffect.CastPetDestroySpell`, which verifies ownership before calling ordinary `Destroy`: `Goose/SpellEffect.cs:938-953`; dispatch to it requires a `Pet` target: `Goose/SpellEffect.cs:1051-1057`.
- `/petspawn` currently compares the database field with monotonic `world.TimeNow` and computes the wait in the wrong direction: `Goose/Commands/PetSpawnCommand.cs:38-48`. `world.TimeNow` is `Stopwatch.GetTimestamp()`, so it is not the persisted clock: `Goose/GameWorld.cs:77-88`.
- `Pet.SaveToDatabase` snapshots `BuildSave` and queues it on the dedicated database thread: `Goose/Pet.cs:299-313`, `Goose/Database.cs:218-271`.
- `Database.Execute` provides a synchronous FIFO barrier for integration assertions after an async save: `Goose/Database.cs:171-216`; `Database.Stop` drains queued and in-flight work: `Goose/Database.cs:281-314`.
- `Player.LoadPets` performs a real database read and reconstructs each pet through `Pet.FromReader`: `Goose/Player.cs:831-865`; `Player.AddPet` restores ownership: `Goose/Player.cs:2614-2622`.
- Command tests can execute `/petspawn` through the real event queue using `TestWorldFixture.RunCommand`: `TestSupport/TestWorldFixture.cs:122-127`.
- Both command and spell work run through `EventHandler.Update` on the game loop path: `Goose/EventHandler.cs:327-360`, `Goose/Events/PlayerCastSpellEvent.cs:15-84`. The new in-memory mutations therefore remain on the established game-thread path; persistence remains queued to the database thread.

## Persistence Strategy

Use the existing `pets.next_respawn_time` column without changing schema creation SQL or adding a migration. Existing zero values mean no cooldown. The current server never writes nonzero values, so treating future nonzero values as UTC Unix seconds is backward-compatible with server-produced data.

### Task 2: Start cooldowns only for death and manual recall

**Files:**
- Modify: `Goose/Pet.cs:62-70,504-544,748-806`
- Modify: `Goose/SpellEffect.cs:938-953`
- Create: `Goose.IntegrationTests/PetCooldownTests.cs`

**Helper contract:**

Add `public void DestroyWithCooldown(GameWorld world)` to `Pet`.

- Ownership: mutates only this pet's `NextRespawnTime` and normal destruction state; it does not alter other pets or owner state.
- Preconditions: callers provide the active `GameWorld`; the intended callers have a live pet. If the pet is already absent, return without setting or saving a cooldown.
- Side effects for a live pet: set expiry to current UTC Unix seconds plus the private 120-second constant, queue `SaveToDatabase(world)`, then invoke `Destroy(world)`.
- Side effects intentionally excluded: no packets beyond those already sent by `Destroy`, no event registration, no owner-wide save, and no cooldown extension from ordinary `Destroy`.
- Postconditions: the pet is absent from the map and login-ID registry, the in-memory expiry is approximately 120 seconds in the future, and a database write containing that expiry is queued.
- Failure behavior: the in-memory timestamp remains authoritative for the running session. Database work uses the existing asynchronous save behavior; a database execution failure is logged by `Database`, and a later regular pet/player save can retry the in-memory value. Do not add blocking database I/O to the game thread.

**Mutation impact:**
- Source of truth changed: `Pet.NextRespawnTime` at `Goose/Pet.cs:62-65`.
- Important readers: `/petspawn` at `Goose/Commands/PetSpawnCommand.cs:38-48`, persistence at `Goose/Pet.cs:299-454`, loading at `Goose/Pet.cs:201-290`.
- Derived/cached state affected: pet map placement, `Pet.LoginIDToPet`, map player membership, tile occupancy, and NPC aggro are already torn down by `Pet.Destroy` at `Goose/Pet.cs:508-544`. No new cache is introduced.
- Required propagation sequence:
  1. Verify the pet is alive.
  2. Set the UTC expiry in memory.
  3. Call `SaveToDatabase(world)` so `BuildSave` snapshots the new value and queues it.
  4. Call existing `Destroy(world)` to perform all established map/registry teardown.
  5. On a synchronous database queueing exception, preserve existing event containment through `EventHandler.Update`; do not perform database work directly on the game thread.
- Invariants to preserve:
  - Death and successful owner recall each start one fresh 120-second cooldown.
  - A non-owner recall still returns `false` and changes nothing.
  - Ordinary `Destroy` remains cooldown-free for logout, map changes, idling, deletion, and internal spawn cleanup.
  - An already-absent pet cannot acquire or extend a cooldown through the dedicated method.
  - Registry publication/teardown ordering stays inside existing `Destroy`; the new helper must not duplicate partial teardown.
- Observable proof required:
  - Tests assert final map absence, timestamp range, database/reloaded value, and unchanged timestamp for ordinary destruction—not merely that a method was invoked.

### Task 3: Enforce and report the persisted cooldown in `/petspawn`

**Files:**
- Modify: `Goose/Commands/PetSpawnCommand.cs:38-48`
- Test: `Goose.Tests/Part2PetsTests.cs:51-111`

**Mutation impact:**
- Source of truth changed: no new mutation; this task changes validation of `Pet.NextRespawnTime` from the wrong monotonic clock to UTC Unix seconds.
- Important readers: `/petspawn` is the only runtime cooldown reader found by repository search: `Goose/Commands/PetSpawnCommand.cs:38-48`.
- Derived/cached state affected: No derived state found. A rejected command leaves map placement, vitals, expiry, and other pets unchanged.
- Required propagation sequence:
  1. Resolve the requested owned pet through the existing lookup.
  2. Read current UTC Unix seconds once.
  3. If expiry is greater than now, calculate `expiry - now`, send the rejection, and return without invoking `Spawn`.
  4. Otherwise invoke the existing `Pet.Spawn` path unchanged.
- Invariants to preserve:
  - Remaining time is positive and never displays the current negative-value bug.
  - A blocked attempt does not mutate or extend the expiry.
  - Expiry equal to the current second is allowed.
  - Cooldowns are per pet; one cooling-down pet does not block a different pet.
  - Existing disabled-map, invalid-ID, missing-pet, and successful-spawn behavior is unchanged.
- Observable proof required:
  - Command tests assert actual map presence/absence, unchanged timestamp, positive message text, boundary success, and independent-pet success.

**Step 3: Implement spawn validation**

In `PetSpawnCommand.Execute`:

- Read `long now = DateTimeOffset.UtcNow.ToUnixTimeSeconds()` after finding the pet.
- Compare `match.NextRespawnTime > now`.
- Calculate remaining whole seconds as `match.NextRespawnTime - now` and send the existing message shape with that positive integer.
- Remove the obsolete floating-point/timer-frequency calculation and its explanatory comment.
- Return before `match.Spawn(world)` when blocked.

Unix-second storage makes the positive integer difference the displayed ceiling at the stored precision; no floating-point rounding is required.
