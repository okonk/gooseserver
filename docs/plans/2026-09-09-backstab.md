# Backstab Spell Effect Implementation Plan

**Goal:** Add a reusable Backstab spell-effect script that attacks the tile in front of the caster, gains 1.5× damage against a same-facing target, and always emits attack and tile animations.

**Architecture:** Extract the existing formula-result calculation from `SpellEffect.CastFormulaSpell` into a public, side-effect-limited helper that scripts can call without duplicating crit, spell-damage, PvP, or global-modifier rules. The Backstab script performs its own one-tile targeting and visual broadcast, validates the discovered occupant through `CanCastSpell`, and applies calculated damage through `ICharacter.Attacked`.

**Tech Stack:** .NET 10, C#, Roslyn `.csx` scripting, xUnit integration tests

## Task 1: Extract formula-result calculation

**Files:**
- Create: `Goose.IntegrationTests/SpellFormulaResultTests.cs`
- Modify: `Goose/SpellEffect.cs:570-627`

**Helper contract:**

Add this public API to `SpellEffect`:

```csharp
public (long HP, long MP) CalculateFormulaResults(
    string hpFormula,
    string mpFormula,
    ICharacter caster,
    ICharacter target,
    GameWorld world)
```

Preconditions: both formulas are valid inputs for `ParseFormula`; caster, target, and world are non-null. The helper parses HP before MP, then preserves the existing HP-then-MP modifier order. It consumes the same random crit draws as the current code when `SpellDamageEffects` is enabled, including for a zero result. It returns processed values but does not mutate either character, send packets, add aggro, or persist anything. It applies `world.Settings.DamageModifier` to HP only, matching current behavior.

**Mutation impact:**
- Source of truth changed: no model field changes; formula strings remain owned by `SpellEffect.HPFormula` and `MPFormula` (`Goose/SpellEffect.cs:129-131`). The execution path in `CastFormulaSpell` is refactored.
- Important readers: ordinary formula and viral casts dispatch through `CastSpell` (`Goose/SpellEffect.cs:1008-1017`); tick processing calls `CastFormulaSpell` from existing buff paths.
- Derived/cached state affected: no cache or persisted state. `GameWorld.Random` state advances during crit checks (`Goose/GameWorld.cs:76-82`) and must preserve draw count/order.
- Required propagation sequence:
  1. Parse both formulas.
  2. Apply HP crit/spell-damage rules.
  3. Apply MP crit/spell-damage rules.
  4. Apply the global modifier to HP.
  5. Return both values to `CastFormulaSpell`.
  6. Let existing code mutate MP, call `Attacked`, and send packets unchanged.
- Invariants to preserve:
  - Damaging player targets continue to bypass spell crit and spell-damage scaling.
  - NPC damage and positive player effects retain spell scaling.
  - Global `DamageModifier` affects HP but not MP.
  - No additional or reordered RNG draws occur in ordinary formula casts.
  - Existing target mutation and packet behavior remain outside the helper.
- Observable proof required: tests assert returned HP/MP values and final real target state after `CastFormulaSpell`, not merely helper invocation.

## Task 2: Add and test the Backstab script

**Files:**
- Create: `Goose/Data/Illutia/Scripts/Spell/Backstab.csx`
- Create: `Goose.IntegrationTests/BackstabScriptTests.cs`
- Modify: `Goose.IntegrationTests/Goose.IntegrationTests.csproj:15-53`

**Mutation impact:**
- Source of truth changed: no persisted spell data changes. Runtime multiplier input is `SpellEffect.ScriptParams` (`Goose/SpellEffect.cs:222-224`); caster and victim runtime state remains authoritative on their `ICharacter` instances.
- Important readers: the script is invoked only when a configured effect points to it through `SpellHandler` script loading (`Goose/SpellHandler.cs:138-143`). Existing Backstab rows are intentionally not rewired.
- Derived/cached state affected: target HP, NPC aggro/combat events or player status packets created by the existing `Attacked` implementation. No cached or persisted spell metadata changes.
- Required propagation sequence:
  1. Compute the front coordinate from caster facing.
  2. Send one combined attack/tile-animation packet to the caster and every player returned by `GetPlayersInRange(caster)`.
  3. Resolve the occupant with `GetCharacterAt`.
  4. Reject empty or ineligible occupants without mutating HP.
  5. Parse/fallback the multiplier and calculate formula results.
  6. Apply the same-facing bonus to processed HP damage.
  7. Call `occupant.Attacked(caster, damage, world)` so existing combat propagation runs.
- Invariants to preserve:
  - Nominal self target is never used as the victim lookup.
  - Exactly one tile in front is considered.
  - Animation occurs for a hit, empty tile, rejected target, and out-of-bounds coordinate.
  - Missing, malformed, zero, or negative multipliers behave as `2`.
  - Same-facing bonus is applied after existing formula processing.
  - Eligibility remains server-side through `CanCastSpell`.
  - Script use does not require a database/schema migration; operators configure `script_path`, `script_params`, and script effect type separately.
- Observable proof required: integration tests assert real HP mutation and exact captured `ATT`/`SPA` packet contents.

**Step 5: Implement `Backstab.csx`**

Implement a stateless `Backstab : BaseSpellEffectScript` and return `typeof(Backstab)` at the end of the script.

Key implementation details:

- Use the same facing switch as `LineFront` for values 1–4.
- Build the attack and tile animation into one delimiter-separated packet.
- Send directly to `caster` when it is a `Player`, because `GetPlayersInRange` excludes the center character; then send to all nearby players.
- Do not gate `P.SpellTile` on animation ID or map bounds.
- Parse params with `decimal.TryParse` and `CultureInfo.InvariantCulture`; replace any non-positive result with `2m`.
- Format the multiplier invariantly into `-<multiplier> * (%cstr + %cwdmg + %clevel)` and call `CalculateFormulaResults(formula, "0", caster, occupant, world)`.
- Convert the negative HP result to positive damage. Apply `1.5m` after helper processing when facings match, using the established `long` cast behavior, and call `Attacked` only for positive damage.
- Return true for both hits and misses.
- Add no comments or docstrings.
